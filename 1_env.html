왜 R Script인가? (5분)

현재 많은 연구자의 워크플로우

Excel에서 데이터 정리 → SPSS에서 분석 → 결과를 Word에 복붙 → 리뷰어 코멘트 → 처음부터 다시...
Warning이 과정에서 생기는 문제들
  • 데이터 수정 → 표/그래프 전부 수작업으로 다시 만들기
  • “이 p-value 어디서 나온 거였지?” → 추적 불가
  • 공동연구자에게 분석 과정 전달 → 구두 설명 or 스크린샷

R Script 파이프라인이란

input: 연구 데이터 ➡️ R script ➡️ output: 논문용 표 & 그래프 📊📈

핵심은 “스크립트 = 분석 기록” 이라는 점입니다.

기존 방식 (SPSS/Excel) R Script 파이프라인
데이터 수정 시 표/그래프 전부 다시 스크립트 재실행 (1초)
분석 과정 공유 구두 설명, 스크린샷 .R 파일 전달
리뷰어 수정 요청 처음부터 다시 해당 줄만 수정 후 재실행
휴먼 에러 복붙 실수, 오타 코드가 동일하면 결과도 동일
Reproducibility ❌ ✅
Tip실제 시나리오

리뷰어: “Table 1에서 BMI 대신 BSA를 써주세요”

  • SPSS: 변수 바꾸고 → 분석 다시 돌리고 → 표 다시 만들고 → Word에 다시 붙이고…
  • R Script: 변수명 한 줄 수정 → 스크립트 실행 → 끝

R Project: 파일 관리의 정석 (10분)

왜 R Project를 써야 하는가

R Project(.Rproj)를 쓰면:

  • 작업 디렉토리가 자동 설정됩니다 — setwd() 지옥에서 해방
  • 프로젝트별로 독립된 환경 유지
  • 다른 컴퓨터에서 열어도 경로 문제 없음

권장 폴더 구조

my_research_project/
├── my_research_project.Rproj
├── scripts/          # 분석 스크립트 (.R 파일)
│   ├── 01_preprocessing.R
│   ├── 02_table1.R
│   └── 03_survival.R
├── rawdata/          # 원본 데이터 (절대 수정 금지!)
│   └── clinical_data.xlsx
├── analysis/         # 중간 분석 결과
│   └── cleaned_data.rds
└── results/          # 최종 산출물
    ├── Table1.docx
    ├── KM_curve.tiff
    └── forest_plot.tiff
Important핵심 원칙
  1. rawdata는 절대 건드리지 않는다 — 원본은 읽기만 하고, 전처리 결과는 analysis/에 저장
  2. 스크립트에 번호를 붙인다 — 실행 순서가 명확해짐
  3. results에는 최종본만 — 논문에 바로 들어갈 표와 그림

실습: R Project 만들기

RStudio에서:

File → New Project → New Directory → New Project
→ 프로젝트 이름 입력 (예: "SBRT_survival")
→ Create Project

그 다음 콘솔에서 폴더 생성:

# 폴더 구조 한 번에 만들기
dir.create("scripts")
dir.create("rawdata")
dir.create("analysis")
dir.create("results")

R Script 작성 기본 습관 (10분)

스크립트 구조 템플릿

모든 분석 스크립트는 이 구조를 따르면 됩니다:

# ============================================================
# 프로젝트: SBRT 간암 생존분석
# 스크립트: 01_preprocessing.R
# 작성자: 하은지
# 최종수정: 2026-05-13
# ============================================================

# 1. 패키지 로딩 -----
library(tidyverse)
library(readxl)

# 2. 데이터 읽기 -----
raw <- read_excel("rawdata/clinical_data.xlsx")

# 3. 전처리 -----
df <- raw |>
  filter(!is.na(survival_time)) |>
  mutate(
    age_group = ifelse(age >= 65, "≥65", "<65"),
    event = as.numeric(status == "dead")
  )

# 4. 결과 저장 -----
saveRDS(df, "analysis/cleaned_data.rds")

핵심 습관 3가지

1. 주석은 “왜”를 적는다

# 나쁜 주석
filter(age >= 18)  # 18세 이상 필터 (코드 보면 알잖아요)

# 좋은 주석
filter(age >= 18)  # IRB 승인 기준: 성인 환자만 포함

2. 하드코딩 금지

# 나쁜 예
df <- read_excel("/Users/eunji/Desktop/논문/데이터/final_data_v3_진짜최종.xlsx")

# 좋은 예 (R Project 안에서)
df <- read_excel("rawdata/clinical_data.xlsx")

3. 중간 결과 저장

# 전처리가 오래 걸리면 .rds로 저장해두기
saveRDS(df_cleaned, "analysis/cleaned_data.rds")

# 다음 스크립트에서 바로 불러오기
df <- readRDS("analysis/cleaned_data.rds")

핵심 패키지 미리보기 (5분)

Part 2~3에서 사용할 패키지를 미리 설치합니다.

# 한 번만 실행하면 됩니다
install.packages(c(
  "tidyverse",    # 데이터 전처리 + 시각화
  "readxl",       # 엑셀 파일 읽기
  "gtsummary",    # Table 1 자동 생성
  "survival",     # 생존분석
  "survminer",    # KM curve 시각화
  "broom",        # 통계 결과 → 데이터프레임
  "forestploter"  # Forest plot
))
Note설치가 안 될 때 
# 특정 패키지가 에러나면 하나씩 설치
install.packages("gtsummary")

# 그래도 안 되면 버전 확인
R.version.string

Part 1 정리

✅ R Script = 분석 기록 → 재현성 확보
✅ R Project = 프로젝트별 독립 환경 → 경로 문제 해결
✅ 폴더 구조: rawdata / scripts / analysis / results
✅ 스크립트 습관: 헤더, 주석, 상대경로, 중간저장

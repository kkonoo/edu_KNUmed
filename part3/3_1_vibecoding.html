바이브코딩이란?

AI에게 자연어로 설명 → 코드 생성 → 실행 → 수정 반복

코드를 “외우는” 것이 아니라, AI에게 잘 시키는 법을 배우는 것입니다.

프롬프트의 3요소

좋은 프롬프트 = 역할 + 맥락 + 구체적 요청

나쁜 프롬프트

통계 분석 해줘

→ AI가 뭘 해야 할지 모름. 쓸모없는 결과가 나옴.

좋은 프롬프트

너는 임상통계 전문가야.

나는 올리고전이 환자 대상 SBRT 논문을 쓰고 있어.
데이터프레임 df_pt에 다음 변수가 있어:
- Age_Tx: 치료 시 나이 (연속형)
- Sex: 성별 (M/F)
- Primary: 원발 부위 (Colon, Rectum, Lung 등)
- Death: 사망 여부 (0/1)
- OS: 전체 생존 기간 (개월)
- size_cm: 종양 크기 (cm)
- PTVmean_BED10: PTV 평균 BED10 (Gy)

다음을 수행하는 R 코드를 작성해줘:
1. gtsummary로 Table 1 생성 (Death 기준 그룹 비교, p-value 포함)
2. 변수명은 논문용 라벨로 변환
3. results/Table1.docx로 저장
Tip프롬프트 작성 팁
  1. colnames(df) 결과를 붙여넣기 — AI가 변수명을 정확히 알아야 함
  2. 변수 타입 명시 — 연속형/범주형/생존시간 구분
  3. 원하는 출력 형태 지정 — “Word로 저장”, “tiff 300dpi”, “forest plot” 등
  4. 패키지 지정 — “gtsummary로”, “survminer로” 등

실전 워크플로우

바이브코딩의 현실적인 작업 흐름은 이렇습니다:

1. RStudio에서 rds 로드
2. AI가 만든 코드를 콘솔에 붙여넣기 & 실행
3. 에러 → 에러 메시지를 AI에게 복붙 → 수정 코드 받기
4. 중간 결과 확인 (head, str, plot 등)
5. 만족하면 .R 파일로 저장
6. input → output 구조의 스크립트 완성

핵심은 처음부터 완벽한 스크립트를 만들려 하지 않는 것입니다. RStudio 콘솔에서 한 줄씩 돌려보고, 중간 과정을 계속 트러블슈팅해서 최종적으로 동작하는 코드가 완성되면 그때 파일로 저장합니다.

Step 2. AI에게 프롬프트 작성

colnames()과 str() 결과를 붙여넣고, 원하는 분석을 요청합니다.

위 데이터에서 생존분석을 해줘.

- Kaplan-Meier curve: Death/OS 기준, Multiplicity(single vs multiple)로 그룹 비교
- Log-rank test p-value를 그래프에 표시
- Risk table 포함
- survminer 패키지 사용
- 300 dpi tiff로 저장

Step 3. AI가 준 코드를 콘솔에서 실행

AI가 생성한 코드를 한 블록씩 RStudio 콘솔에 붙여넣어 실행합니다.

library(survival)
library(survminer)

# Kaplan-Meier fit
fit <- survfit(Surv(OS, Death) ~ Multiplicity, data = df_pt)

# KM curve
p <- ggsurvplot(
  fit,
  data = df_pt,
  pval = TRUE,
  risk.table = TRUE,
  xlab = "Time (months)",
  ylab = "Overall survival",
  palette = c("#2E86AB", "#A23B72"),
  ggtheme = theme_minimal()
)

print(p)

Step 4. 에러가 나면?

에러 메시지를 그대로 복붙해서 AI에게 주면 됩니다.

이 코드를 실행했더니 다음 에러가 났어:

Error in data.frame(..., check.names = FALSE) : 
  arguments imply differing number of rows: 54, 0, 108

고쳐줘.

→ AI가 Death가 factor라서 Surv()에서 인식 못하는 걸 잡아줌

이런 식으로 실행 → 에러 → AI에게 복붙 → 수정을 반복합니다.

Step 5. 동작 확인되면 스크립트로 저장

콘솔에서 다 돌아가는 걸 확인했으면, 코드를 모아서 .R 파일로 저장합니다. 이때 상단에 input/output을 명시하고, 경로를 paste0()로 정리합니다.

# ===== 03_KM_plot.R =====
# Input:  analysis/2_df_pt_processed.rds
# Output: results/KM_OS.tiff, results/KM_OS.pdf

# ----- 디렉토리 -----
indir  <- "analysis/"
resdir <- "results/"

library(tidyverse)
library(survival)
library(survminer)

# 1. 데이터 로드
df_pt <- readRDS(paste0(indir, "2_df_pt_processed.rds"))

# 2. KM fit
fit <- survfit(Surv(OS, Death) ~ Multiplicity, data = df_pt)

# 3. Plot
p <- ggsurvplot(
  fit,
  data = df_pt,
  pval = TRUE,
  risk.table = TRUE,
  xlab = "Time (months)",
  ylab = "Overall survival",
  palette = c("#2E86AB", "#A23B72"),
  ggtheme = theme_minimal()
)

# 4. 저장
tiff(paste0(resdir, "KM_OS.tiff"), width = 7, height = 5, units = "in", res = 300)
print(p)
dev.off()

ggsave(paste0(resdir, "KM_OS.pdf"), plot = print(p), width = 7, height = 5)

cat("✅ KM plot saved!\n")

이렇게 적어두면 나중에 파일만 봐도 이 스크립트가 뭘 읽고 뭘 만드는지 바로 알 수 있습니다.

AI가 틀리기 쉬운 통계적 함정 (사전 지식이 중요한 이유)

Warning
  1. Reference level 방향 — relevel(factor, ref = "baseline")을 빠뜨리는 경우 많음
  2. 환자 vs 병변 단위 혼동 — OS는 환자 단위, LFFS는 병변 단위
  3. 다중비교 보정 누락 — subgroup 여러 개 비교하면서 Bonferroni 안 하는 경우
  4. 결측치 처리 — 기본값이 na.rm = FALSE라 결과가 NA로 나올 수 있음
  5. 생존 시간/이벤트 뒤바꿈 — Surv(time, event) 순서 주의

이것들은 사람이 알아야 합니다. Part 1에서 Base R로 직접 해본 이유가 여기 있어요.
